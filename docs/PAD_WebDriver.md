# Power Automate Desktop 無料版 (PAD) と WebDriver だけでバッチ実行する（ブラウザ拡張機能は不要）

> **PAD 版は手動ログイン方式専用。**
> 人が画面でログインした後に開始させる方式。
> **ID・パスワードは一切扱わない安心・安全設計。**

Power Automate Desktop 無料版（PAD）は、プログラム言語で開発するより遥かに簡単に
自動化を実現できる素晴らしいソフトだと思いますが、それでも一般の人からすると
簡単ではないと思います。
そこで、**ブラウザ操作の自動化に特化させることにより PAD での自動化を簡単にする
支援ツール**として作りました。

**1 件ずつ手でやっていた画面操作を、明細の件数ぶんまとめて流せます。**

たとえば「発注番号で検索して、受諾して、画面を保存する」を 50 件。
これまで 50 回繰り返していた操作が、明細の CSV を用意して実行するだけになります。

### 使う人がすることは 4 つ

```
① 1 件ぶんの操作をブラウザーで録画する（Chrome / Edge の標準機能）
② 変換器に読み込ませて、PAD に貼るコードを作る
③ PAD に貼って実行する
④ ログインして[OK]を押す ← あとは自動
```

**②で JSON を書く必要はありません。** 画面に操作が一覧で出るので、
「これは 1 件ごとに繰り返す」「ここは毎回変わる値」と選ぶだけです。

### 終わったあとに残るもの

| | |
| --- | --- |
| エビデンス | 1 件ごとの画面写真、またはダウンロードしたファイル |
| 結果 CSV | どの明細が成功・失敗したか、理由つき |
| 進捗ログ | 実行の記録。途中で止まったときの手がかり |

**失敗した行だけをもう一度流せます。** 全部やり直す必要はありません。

## 💡Power Automate Desktop 無料版 (PAD) 標準の録画機能との違い

本ツール
- ブラウザ自動化バッチ処理に特化し、バッチ運用フロー設定を自動追加し、はまり回避対策をしたPADコード(Robin)に変換する設計。
- DevTools Recorder機能があるブラウザさえあれば操作録画できる。
- 全体のフロー制御はPADを使うが、主なブラウザのコントロールやDOMベース要素インデックス方式はJavaScriptで作ったプログラムをRobinに埋め込み実現。
- 直接WebDriverを操作するのでブラウザ拡張機能なしで使える。

Power Automate Desktop 無料版 (PAD)
- PAD標準の操作録画機能は全般的な用途に使えるように操作をアクションとしてそのまま登録するだけになっている。

## 🧭 全体像

### PAD とブラウザーの間に「WebDriver」がいる

```
Power Automate Desktop
      │  「この要素を押して」と指示を送る
      ▼
  WebDriver（msedgedriver.exe / chromedriver.exe）
      │
      ▼
  Edge / Chrome
```

ブラウザーを実際に動かしているのは PAD ではなく **WebDriver** という部品です。
PAD は指示を送るだけで、**画面の座標も画像も使いません。**

そのおかげで、

- ウィンドウの位置がずれても動く
- 画面の解像度が違う PC でも動く
- 画面を見ていなくても動く（最小化していても構わない）

**ブラウザーの拡張機能は要りません。** WebDriver はブラウザーに付属する
正規の部品で、Microsoft と Google がそれぞれ配布しています。
このツールが自動で取ってきて、更新にも追従します。

### どこまでを PAD がやるか

| すること | 担当 |
| --- | --- |
| 明細の読み込み、件数の繰り返し、結果の記録、失敗した行の再実行 | **PAD** |
| 画面を開く、押す、入力する、エビデンスを撮る | **WebDriver** |

PAD が得意な「表を回す」ところは PAD に、ブラウザー操作は WebDriver に、
という分担です。

> **仕組みをもっと知りたい方へ。** PAD からどんな指示を送っているか、
> なぜ拡張機能なしで動くのかは
> [PAD_WebDriver_internals.md](PAD_WebDriver_internals.md) にまとめてあります。

## 🛠️ 事前準備

1. **💡本ツールは自動でブラウザのバージョンをチェックして、同じバージョンの WebDriver を自動取得し入れ替える機能がある。（後述）**　　

　　もし、WebDriverを自動取得できない環境の場合は手動でダウンロードする。 <br>
　　[Microsoft Edge を自動操作する場合の WebDriver](https://developer.microsoft.com/ja-jp/microsoft-edge/tools/webdriver?form=MA13LH&cs=3787589721) から **msedgedriver.exe** をダウンロードする。　<br>
　　[Google Chrome を自動操作する場合の WebDriver](https://developer.chrome.com/docs/chromedriver?hl=ja) から **chromedriver.exe** をダウンロードする。 <br>

 　　**⚠️ブラウザのバージョンとWebDriverのバージョンは一致させる必要がある。** <br>
 　　ブラウザのバージョンが更新されたら同じバージョンに入れ替える。　<br>

　　msedgedriver.exe と chromedriver.exe は技術的にはどちらもChromiumエンジンを基にしているため、 <br>
　　コードの書き方やAPI（操作コマンド）、DevTools は、ほぼ共通で違いはごくわずかで、ほぼ対象ブラウザが Edge か Chrome かの違い。<br>

2. **プロキシ除外**: 社内プロキシがあると `localhost` 宛が失敗する。Windows のプロキシ設定で
   `localhost;127.0.0.1` を除外に入れる（Ollama で `NO_PROXY=localhost` を設定したのと同じ対策）。

3. **フローの先頭で古いドライバーを終了させる。** 前回の実行が異常終了すると
   `msedgedriver.exe` がポート 9515 を掴んだまま残り、新しいドライバーが起動できない。 <br>
   その状態では**古い方が応答してしまい**、ブラウザーとバージョンが違えば `session not created` になる。 <br>
   Edge と Chrome のフローを続けて動かす場合も同じポートを奪い合うため、両方を終了させておく。

```
System.TerminateProcess.TerminateProcessByName ProcessName: $'''msedgedriver'''
System.TerminateProcess.TerminateProcessByName ProcessName: $'''chromedriver'''
WAIT 1
System.RunApplication.RunApplication ApplicationPath: DriverExe CommandLineArguments: $'''--port=9515''' WindowStyle: System.ProcessWindowStyle.Hidden ProcessId=> DriverPid
WAIT 3
```

`taskkill` を「アプリケーションの実行」で呼ぶ必要はない。`System.TerminateProcess` で足りる。

## 🔄 自動 WebDriver 取得更新機能

**通常は、入っているブラウザーに合わせて WebDriver を自動で取得・更新する。**
ブラウザーが更新されても入れ替え作業は要らない。取得したものは
`C:\temp\driver\<版>\` に置かれ、版が変わると自動的に取り直しになる。

使うのは Windows に最初から入っている `curl.exe` / `tar.exe` / `powershell.exe` だけで、
落ちてくる WebDriver もベンダー署名付き。**持ち込みの実行ファイルを止める環境でも動く。**

> **ネットワークの制限で自動取得が働かない場合は、手作業で WebDriver を置く必要がある。**
> 手順と、取得先の切り替え（`DriverSource`）は
> [PAD_WebDriver_internals.md](PAD_WebDriver_internals.md#-webdriver-の自動取得) を参照。

## 🌐 プロキシ経由でインターネットへ出る環境（企業のネット環境に多い）

**WebDriver が起動するブラウザーは素のプロファイル**で立ち上がり、Windows のプロキシ設定を
引き継がない。そのため、手動のブラウザーでは見えるサイトが WebDriver 経由では真っ白になる。
`localhost` と `file://` はプロキシを通らないので、練習サイトだけは影響を受けない。

セッション開始の本文に `proxy` を渡すと解決する。生成物では冒頭のスイッチで切り替えられる。

```
SET UseProxy TO True
SET ProxyAddr TO $'''proxy.example.com:8080'''
…
SET SessionBody TO $'''{"capabilities": {"alwaysMatch": {"browserName": "MicrosoftEdge"}}}'''
IF UseProxy THEN
    SET SessionBody TO $'''{"capabilities": {"alwaysMatch": {"browserName": "MicrosoftEdge", "proxy": {"proxyType": "manual", "httpProxy": "%ProxyAddr%", "sslProxy": "%ProxyAddr%"}}}}'''
END
```

- SET UseProxy TO True か False　でプロキシ設定を切り替える。
- アドレスは **`host:port` の形**で書く（`http://` は付けない）。
- Edge / Chrome 系は `sslProxy` を見ないことがあるため、`httpProxy` と両方に同じ値を入れる。
- プロキシのアドレスは Windows の「設定 → ネットワークとインターネット → プロキシ」で確認できる。
  `netsh winhttp show proxy` が「直接アクセス」と出ても、ブラウザー側に設定されていることがある。

**フローを触る前にプロキシ自体を検証しておくと切り分けが速い。** コマンドプロンプトで次を実行し、
`HTTP/1.1 200` が返ればアドレスとポートは正しい。

```
curl -x http://proxy.example.com:8080 https://example.com -I
```

> **⚠️ 認証プロキシの場合**
> ユーザー名・パスワードを要求するプロキシでは `proxyType: manual` だけでは通らないことがある。
> まず認証なしで試し、通らなければネットワーク管理者に方式を確認する。

## 📄 明細の CSV について

**1 行が 1 件の処理**になります。1 列目が ID 列で、進捗ログ・結果 CSV・
エビデンスのファイル名に使われます。

```
プロジェクト番号,発注番号,skip
PM9000000001,900000000001,
PM9000000002,900000000002,1     ← skip 列に何か書くとこの行は飛ばす
```

### 文字コードは「CSV UTF-8（コンマ区切り）」

### メモ帳で開く ※推奨

**Windows 11 標準のメモ帳は、CSV UTF-8 のファイルを文字化けせずに開けます。**
中身をちょっと確かめたいときはこれが一番早いです。

### Excel で開く場合

**ファイルをダブルクリックしないこと。** 文字化けしたり、番号が
`9E+11` のような表示になったりします。次の手順で開いてください。

1. 先に Excel を起動する（空白のブックを開く）
2. 上のメニューから「データ」タブ →「テキストまたは CSV から」
3. CSV ファイルを選んで「データの取り込み」。プレビューが出ます
4. 右上の**「元のファイル」を UTF-8** にして、文字が正しく読めるか確かめる
5. 区切り記号が「コンマ」になっていることを確かめる
6. **「データの変換」を押し、発注番号などの列を選んで「データ型」を「テキスト」に**
7. 「閉じて読み込む」

**6 が大事です。** ここを飛ばすと、12 桁以上の番号が `9E+11` のような
指数表記になります。**表示形式を「数値」に直しても、丸められた値は戻りません。**
最初からテキストとして読み込むのが確実です。

## 🤖 録画JSONファイルをPADコード(Robin)へ変換する

PAD のフローは内部的に **Robin 言語**で表現されており、フローデザイナーのキャンバスに
**Robin のテキストを貼り付ける（Ctrl+V）とアクションが並ぶ**。この性質を使い、
**Chrome等の DevTools Recorder でブラウザ操作を録画し JSONでエクスポートし バッチ定義 JSON 編集後に生成器で PAD のフローへ変換生成する**のがこの節の内容。

**アクションを 1 つずつ手で置く必要がない。**
それ以上に重要なのは、 **この手順書に書かれた落とし穴の回避策がすべて生成器に組み込まれている** 
ことで、`EncodeRequestBody: False` の指定漏れや
`SET` の右辺の `%` 誤用のような、貼り付けが黙って無視される類のミスを踏まなくなる。




### 🌐 変換はブラウザーで行う

変換器 `tools/pad_converter.html` を**ブラウザーで開くだけ**です。
インストールも通信もありません。録画 JSON を読み込ませ、画面で選んで、
できたコードを PAD に貼り付けます。

> Python が使える環境なら、コマンドラインの変換器（`pad_webdriver_ref.py`）も
> あります。**出力は 1 文字も変わりません。**
> 使い方は [上級者向け](#-上級者向け) を参照。

### 手順 ①〜③：録画したものを「バッチ定義」に書き換える

録画のしかたは README の「🎥 ブラウザに内蔵されている DevTools の Recorder でブラウザ操作録画 → 決定論リプレイ（拡張機能不要）」を参照。

#### いちばん簡単なやり方：振り分け画面を使う

**ブラウザ版の変換器に録画 JSON を読み込ませると、「1-2. 操作の振り分け」が出る。**
JSON を一度も見ずに、選ぶだけでバッチ定義を作れる。

| 列 | すること |
| --- | --- |
| 起点 | 1 件ごとの繰り返しが**どこから始まると認識されたか**を `▶ 起点` で示す |
| 操作 | 「『検索』を押す」のように、何をする操作かが日本語で出る |
| 録画された指定 | `aria/検索` のような、録画そのままの書き方。**見比べると読み方が分かる** |
| 箱 | setup / loop / loop+復帰 / teardown / 使わない から選ぶ（下の表を参照） |
| 値の扱い | そのまま / 毎回変わる値（列名を入れる） |
| この後にエビデンス | チェックすると、その位置でエビデンスを保存する |
| ダウンロード | チェックすると、その操作で落ちてくるファイルを保存する |

#### 箱の選び方

| 箱 | いつ動くか | 入れるもの |
| --- | --- | --- |
| `setup` | 最初に 1 回だけ | ページを開く、起点画面までメニューを辿る |
| `loop` | 明細 1 件ごと | 検索・入力・実行・エビデンス保存 |
| `loop+復帰` | 1 件ごと **＋** 失敗した次の件の前 | **起点へ戻る操作** |
| `teardown` | 最後に 1 回（省略可） | ログアウトなど |
| `使わない` | 動かない | 録画に混ざった余計な操作、ログイン操作 |

**`loop+復帰` は複数行になることが多い。** 起点へ戻るのに数手かかるなら、
**その全部を `loop+復帰` にする。** 練習用のバッチ定義では 4 手ある。

```
ホーム → 仕入先 → 取引情報入力・照会 → ホームページ   ← この 4 行すべて
```

1 件の終わりにこの道を通り、失敗した次の件の前にも同じ道を通る。**途中の
1 行だけを `loop+復帰` にすると、復帰したつもりで別の画面から始まる。**

`使わない` にした行はバッチ定義に残らない。あとから戻したいときは、元の
録画 JSON からやり直すことになる。

**「起点」を最初に確かめる。** 一覧の上にも行番号と操作名が出る。ここが違っていれば、
正しい行の「ここを起点に」を押せば、その前は `setup`、その後は `loop` へまとめて振り直される。

**箱と値は推測して選んである。** 違うところだけ直せばよい。推測の規則はこう。

- ページを開く・ウィンドウサイズ → `setup`
- ユーザー名・パスワードらしい入力欄 → 「使わない」（変換に含めない）
- 「ログイン」らしいクリックまで → `setup`
- **最後の操作と同じものが前にも出ていたら、そこが繰り返しの起点**。
  その直後から `loop`、最後の戻る操作は `loop+復帰`
- 値を入れている箇所 → 「毎回変わる値」の候補（列名だけ自分で入れる）

箱を「使わない」にした行は、値の扱いを指定しなくてよい（自動で無効になる）。

#### 検索結果の行をクリックする操作

「発注番号で検索して、出てきた行をクリックする」という流れがよくある。このとき
**クリック先も毎回変わる**。録画にはそのときの番号がそのまま入っている。

```
録画されたまま                          書き換えたあと
"selectors": [["aria/900000000001"],    "selectors": [["aria/{{発注番号}}"],
              ["id/N58:PosPoNumber:0"]]                ["text/{{発注番号}}"]]
```

振り分け画面は、**さきほど入力欄に打った値がクリック先の指定にも入っていれば**
「毎回変わる値」として拾う。列名を入れれば置き換わる。

**このとき、その値を含まない候補は捨てる。** 上の例の `id/N58:PosPoNumber:0` は
「一覧の 1 行目」を指す書き方で、番号とは無関係。番号で当たらなかったときに
こちらへ落ちると、**別の案件の行を押してしまい、しかも気づけない。**
残すのは番号を含む候補だけにする。

自分で書く場合も同じ。**位置で指す候補は消しておくこと。**

キー入力の記録（`keyDown` など）は変換に使わないので隠している。実際の録画では
121 件のうち 95 件がこれだった。

読み込んだファイルが録画かバッチ定義かは、画面のメッセージで知らせる。**バッチ定義を読み込んだときは振り分け画面は出ない**（すでに済んでいるため）。やり直したいときは「最初からやり直す」を押す。実行環境のパスは残る。

#### 録画は 1 件ぶんだけにする

**繰り返す 1 件の操作だけを録画する。** 2 件ぶん録ると、振り分け画面の推測が
「1 件目ぜんぶが起点までの準備」と読み違える。2 件目は「使わない」に倒すか、
起点の行で「ここを起点に」を押して直すことになる。

```
録画開始（ログイン直後）→ 起点まで進む → 1 件処理する → 起点へ戻る → 録画停止
```

#### 同じ名前の要素があると押し間違える

録画は `aria/発注` のように**画面に出ている名前**を先頭の候補にする。
同じ名前が画面に複数あると、別の要素に当たることがある。押しても何も
起きない要素でもクリックは成功するので、そのまま先へ進んで後のステップで落ちる。

変換器は `#id` を持つ候補を先頭に寄せるので、たいていはこれで当たる。
それでも外れる場合は、バッチ定義から名前の候補を消す。

```json
{"type": "click", "selectors": [["#POS_ORDERS"]]}
```

#### エビデンスの名前

**書式は生成物の冒頭で決まる。** 1 件ごとにその行の値へ置き換わる。

```
SET ShotNameFmt TO $'''@ID@__@KEY@__@STAMP@'''
```

| 差し込み | 入る値 |
| --- | --- |
| `@ID@` | ID 列（明細 CSV の 1 列目、または指定した列） |
| `@KEY@` | 業務キー（2 列目） |
| `@STAMP@` | 実行日時（`yyyyMMdd_HHmmss`） |

変換器の「エビデンスのファイル名」で決められる。**貼り付けたあとでも、
冒頭の 1 行を直せば変わる。**

```
SET ShotNameFmt TO $'''【注文受諾】@ID@_〇〇株式会社'''
   → 【注文受諾】PM9000000001_〇〇株式会社.png
```

ダウンロードの保存名（`download` の `name`）でも同じ記号が使える。
明細の他の列を使いたいときは `{{列名}}` と書く。

#### 直しては試す、を繰り返す

**振り分け画面はそのまま残る。** 実行してみて具合が悪ければ、表を直して
「この振り分けでバッチ定義を作る」を押し直せば、新しいバッチ定義になる。

```
振り分ける → バッチ定義を作る → 変換する → PAD で試す
       ↑                                      │
       └───── 表を直して作り直す ←─────────┘
```

保存したバッチ定義 JSON を読み込んでも振り分け画面が出るので、後日でも直せる。
ただし **「使わない」にした行はバッチ定義に残らないため、復元できない。**
その行を戻したいときは、元の録画 JSON からやり直す。

**「この振り分けでバッチ定義を作る」を必ず押すこと。** これを押さずに
「変換する」を押しても、録画 JSON には開く URL も繰り返す手順も
書かれていないため、中身の無いフローができる（押していない場合は
その旨を表示して止める）。押すと下の欄に結果が出る。**そのまま
「変換する」を押せば PADコードになる。** 保存しておけば、次回は続きから始められる。

以下は、**振り分け画面を使わず自分で書く場合**、または**画面で作ったものを手直しする場合**の説明。

#### 触るのは 2 か所だけ

録画された JSON は、そのままでは「1 回ぶんの操作」でしかない。これを
「明細を何件でも流せる形」に書き換える。**書き換えるのは次の 2 か所だけ。**

```
① 操作を 4 つの箱に振り分ける
② 毎回変わる値を {{列名}} にする
```

**それ以外は触らない。** とくに `selectors` の中身（`#Value_0` や `aria/検索` のような
長い記号の並び）は、録画された内容をそのまま残す。あれは「画面のどこを押すか」を
示すもので、書き換える必要はない。

#### 先に完成形を見る

書き換える前と後を並べる。変わっているのは値の部分だけ。

**録画されたまま**

```json
{
  "type": "change",
  "value": "900000000001",
  "selectors": [["#Value_0"], ["aria/発注番号"]]
}
```

**書き換えたあと**

```json
{
  "type": "change",
  "value": "{{発注番号}}",
  "selectors": [["#Value_0"], ["aria/発注番号"]]
}
```

`"900000000001"` は録画したときにたまたま入力した 1 件の番号。ここを `{{発注番号}}` に
すると、明細 CSV の「発注番号」列の値が 1 件ずつ入る。**これが「何件でも流せる」の中身。**

> **⚠️ 手動ログイン方式です。** ブラウザ操作録画は、必ず手動でログインし、
> **ログインした直後から**録画を開始したものを使用してください。
> ログイン操作は変換に含めません。

#### ① 操作を 4 つの箱に振り分ける

全体をこの形にする。**箱の名前は英語のままにすること**（生成器が名前で見分けている）。

```json
{
  "title":   "発注確認（注文受諾）",
  "setup":   [ …最初に 1 回だけやること… ],
  "loop":    [ …1 件ごとに繰り返すこと… ],
  "recover": [ …失敗したとき元に戻る手順… ],
  "teardown":[ …最後に 1 回だけ（省略可）… ]
}
```

| 箱 | 意味 | 何回動くか | 入れるもの |
| --- | --- | --- | --- |
| `setup` | **最初に 1 回だけやること** | 1 回 | ページを開く、繰り返しの起点画面まで進む（ログインは人が行う） |
| `loop` | **1 件ごとに繰り返すこと** | 明細の件数だけ | 検索、入力、実行、エビデンス保存、起点へ戻る |
| `recover` | **失敗したとき元に戻る手順** | 失敗した次の件の前 | ホームへ戻る、目的の画面まで進み直す |
| `teardown` | **最後に 1 回だけ** | 1 回・省略可 | ログアウトなど |

**迷ったら、この順に自問する。**

```
その操作は、明細 1 件ごとに繰り返しますか？
   はい  → loop
   いいえ ↓
最初に 1 回だけやればよいことですか？
   はい  → setup
   いいえ ↓
全部終わったあとの後始末ですか？
   はい  → teardown
```

`recover` は録画には出てこない。**`setup` の後半（起点画面まで進む部分）をそのまま
コピーして入れる**ことが多い。

#### ② 毎回変わる値を `{{列名}}` にする

明細 CSV の見出しと同じ名前を、二重の波かっこで囲む。

```
明細CSV                          バッチ定義の中
プロジェクト番号,発注番号        "value": "{{発注番号}}"
PM9000000001,900000000001
PM9000000002,900000000002
```

`value` だけでなく、`text`（コメント）や `selectors` の中でも使える。

```json
{"type": "comment", "text": "発注 {{発注番号}} の受諾を開始"}
{"type": "click", "selectors": [["aria/{{発注番号}}"], ["id/N58:PosPoNumber:0"]]}
```

2 つめは「一覧の中から、その発注番号の行を押す」という意味になる。

#### 起点画面の目印を書いておく

`originHint` に、**繰り返しの起点画面で目に入る文字**を書いておくと、
手動ログインと起点確認のダイアログに出る。

```json
{
  "originHint": "納入",
  "title": "納入登録",
  "setup": [ … ],
```

```
起点画面が出ていません。「納入」が見える画面まで進めて[OK]。（1 回目）
```

書かない場合は、繰り返し最初の操作の候補から `aria/` や `text/` の名前を拾う。
それも無いと **`#POS_SHIPMENTS` のような ID しか出せず、画面のどこを指すのか
利用者には分からない。** 一言書いておくだけで迷いが減る。

#### JSON の書き方（3 分で分かる分だけ）

編集はメモ帳でよい。**保存するときは文字コードを UTF-8 にすること。**

```json
{                            ← 全体を波かっこで囲む
  "title": "発注確認",       ← "名前": "値" と書く。両方とも半角の " で囲む
  "loop": [                  ← 複数並べるものは角かっこで囲む
    {"type": "click"},       ← ひとまとまりは波かっこ。区切りはカンマ
    {"type": "change"}       ← 最後の 1 つにはカンマを付けない
  ]
}
```

**壊しやすいのはこの 3 つ。**

| やりがち | 正しい |
| --- | --- |
| 最後の項目のうしろにカンマ `…"change"},` | 最後だけカンマなし |
| 全角の引用符 `”type”` | 半角の `"type"` |
| かっこの閉じ忘れ | `{` と `}`、`[` と `]` の数をそろえる |

日本語はそのまま書いてよい。`"title": "発注確認（注文受諾）"` で問題ない。

**行の先頭が `//` や `#` の行はコメント**として無視される。メモを書き残せる。

```json
// 2026/08 作成。検収状況一覧のエビデンス取得用。
{
  "title": "…",
```

#### 使える操作の種類

録画から出てくるのはほとんど `click` と `change`。それ以外は必要なときだけ手で足す。

| 種類 | 意味 | 書き方 |
| --- | --- | --- |
| `click` | クリック | `{"type": "click", "selectors": [["#btn"]]}` |
| `change` | 入力欄に値を入れる | `{"type": "change", "value": "{{発注番号}}", "selectors": [["#Value_0"]]}` |
| `navigate` | URL を開く | `{"type": "navigate", "url": "https://…"}` |
| `setViewport` | ウィンドウサイズ | `{"type": "setViewport", "width": 1366, "height": 900}` |
| `screenshot` | **エビデンスを保存する** | `{"type": "screenshot", "name": "受諾完了"}` |
| `assertText` | 画面に文字があるか確認 | `{"type": "assertText", "text": "発行しました"}` |
| `download` | **ダウンロードして保存する** | `{"type": "download", "selectors": [["#OutputIcon0"]], "name": "【一覧】{{プロジェクト番号}}"}` |
| `capture` | **画面の値を読み取って記録する** | `{"type": "capture", "selectors": [["#ShipDoneNo"]], "name": "要求ID"}` |
| `comment` | 生成コードにメモを残す | `{"type": "comment", "text": "受諾を開始"}` |

**`screenshot` は録画には出てこない。** エビデンスが要るなら、`loop` の中の
「完了画面が出ている位置」に自分で 1 行足す。ホームへ戻ってから撮っても意味がない。

#### 箱によって使えない種類がある

**書いても無視されるものがある。** 変換したときに警告が出るので、必ず目を通すこと。

| 種類 | setup | loop | recover | teardown |
| --- | :---: | :---: | :---: | :---: |
| `comment` | ○ | ○ | ○ | ○ |
| `click` / `change` | ○ | ○ | ○ | ○ |
| `navigate` | ○ | − | ○ | − |
| `setViewport` | ○ | − | − | − |
| `screenshot` | − | ○ | − | − |
| `assertText` | − | ○ | − | − |
| `download` | − | ○ | − | − |
| `capture` | − | ○ | − | − |

**`loop` に `navigate` は入れられない。** URL を開き直すとログイン画面に戻される
サイトがあるため。1 件ごとの移動は画面のクリックで行う。

**`setup` に `screenshot` と `assertText` は入れられない。** 起点画面に着いたかの
確認は生成器が自動で作るので、書く必要がない。

#### 仕上げの確認

書き換えたら、変換器にかけて警告が出ないことを見る。**これが一番手軽な検算になる。**

- [ ] 全体が `{` で始まり `}` で終わっている
- [ ] `setup` と `loop` がある（`recover` も入れておくと安心）
- [ ] 録画のときに入力した実際の値が残っていない（番号など）
- [ ] `{{列名}}` の名前が明細 CSV の見出しと一字一句同じ
- [ ] `loop` の最後が、次の 1 件を始められる画面で終わっている
- [ ] エビデンスが要るなら `loop` に `screenshot` を入れた
- [ ] 変換器で「変換する」を押し、**警告が出ない**

変換器が出す警告の例。

```
⚠ setup の 2 番目: 種別 'assertText' は setup では無視されます
⚠ 12行: 未解決のプレースホルダが残っています
```

#### 押さえておきたい 2 点

**`loop` の始まりと終わりを同じ画面にそろえる。** 1 件の最後に「ホームへ戻る」などを
入れておけば、次の件が必ず同じ状態から始まる。ここが崩れると、2 件目以降が
「要素が見つかりません」ばかりになって原因が追えなくなる。

**`recover` を必ず書く。** 省略すると、失敗したときに開始 URL を開き直すだけの動きに
なり、ログインが必要なサイトではセッションが切れる。**`recover` が無いと 1 件の失敗が
全件に連鎖する。**

#### 明細 CSV との対応

`{{列名}}` は明細 CSV の見出しと突き合わせる。変換のときに指定する「ID 列」が
進捗ログ・結果 CSV・エビデンスのファイル名のキーになる。

```
プロジェクト番号,発注番号,skip
PM9000000001,900000000001,
PM9000000002,900000000002,1     ← skip 列に何か書くとこの行は飛ばす
```

`skip` 列は任意。値が入っている行は処理せず「スキップ」として記録される。

### 手順 ④：PADコード(Robin)を生成する
#### 一般ユーザー向け: ブラウザ版 `pad_converter.html`　　※ Python などの開発ツール不要

<div align="center"> <img src="SS_pad_converter_html_2.png"> </div>

1. 録画 JSON
ここにドラッグ＆ドロップ、またはファイルを選択

2. 実行環境（PAD を動かす PC）のパス
ここに書いた値は生成物にそのまま埋め込まれます。変換した PC のパスではなく、 PAD を動かす PC のパスを入れてください。
明細ファイル (--details)：   C:\temp\edi2_batch.csv
ID 列 (--id-column)： 　プロジェクト番号
　　　　下の「明細ファイル」を選べば先頭列が自動で入ります
ドライバー (--driver-exe)：　C:\temp\msedgedriver.exe
BaseDir (--pad-out-dir)：  C:\temp

3. オプション
ブラウザー (--pad-browser)：  edge
プロキシ (--proxy) ： 　proxy.example.com:8080
ドライバー自動取得：   --auto-driver
明細ファイル（列名の確認用・任意） ファイルが選択されていません
上の「明細ファイル (--details)」は実行環境のパスを書くだけで、中身は読めません。 
列名を確かめたい場合は、変換するこの PC にある同じ CSV をここで選びます。



#### 生成器が自動で行う変換

| 録画 JSON | 生成される PADコード(Robin) |
| --- | --- |
| `{{列名}}` | ループ先頭で `SET Col1 TO Row['列名']` として取り出し、以降は `%Col1%` で参照 |
| `xpath///*[@id="X"]` | `id/X`（リテラルに引用符を持ち込まないため） |
| 単引用符を含むセレクタ候補 | 生成時に除外（貼り付けが無視されるため） |
| 共通 JavaScript | 1 行 100 文字程度に分割して `SET JsAct TO $'''%JsAct%…'''` で継ぎ足し |

**`%Row['列名']%` を直接使わないのが要点。** リテラル内に単引用符が入ると PAD が
貼り付けを無視するため、ループ先頭で変数へ取り出す形に変換している。

#### 生成される制御構造

録画には含まれない運用機能が自動で付く。すべて手順書の該当節と同じ実装。
**PAD標準の録画機能は単純に操作をアクションにしていくだけだが、この生成器は自動でバッチ運用に必要な要素や、はまりどころの回避策を反映してくれる。**

- **手動ログイン** … 人が手でログインし、そのあとフローが起点画面まで進める。PAD はパスワードを
  一度も受け取らない。録画のログイン操作は変換に含めない
- **セットアップ失敗の検知** … `Halt` が立つと明細を 1 件も流さずに中止する
- **件数制限** … `MaxItems`。打ち切った行は「未実行」として結果に残る
- **skip 列** … 値がある行は飛ばす
- **失敗分の再実行** … `RetryMode = True` で結果 CSV を明細として読み直す
- **失敗後の復帰** … `PrevFailed` を悲観的に立て、次の件の前に `recover` を実行する
- **エビデンス** … WebDriver の `/screenshot`（ブラウザのページだけが写る）＋日時つき命名
- **失敗時エビデンス** … `fail__` 接頭辞で保存する
- **結果 CSV と進捗ログ** … 成功・失敗・スキップ・未実行を 1 行ずつ記録

#### 生成時の自動チェック

書き出しの直前に、実機で判明している落とし穴を機械的に洗って警告する。
**PAD は解釈できない行をエラーも出さずに無視する**ため、生成時に気づけないと
「貼り付けたのにアクションが足りない」という形で後から発覚する。

- 700 文字を超える行
- `SET x TO %y%` … 変数の代入で `%` を使っている
- `EncodeRequestBody: False` の欠落
- リテラル内のエスケープされていない単引用符

**警告が出たら貼り付ける前に直すこと。** 何も出なければそのまま進んでよい。

### 手順 ⑥：Power Automate Desktop 無料版(PAD) に貼り付ける

1. PAD で新しいデスクトップフローを作る（⚠️**Power Fx は有効にしない**）
2. `pad_flow.robin.txt` をテキストエディタで開き、**全選択してコピー**
3. フローデザイナーのキャンバスをクリックしてから **Ctrl+V** で貼り付ける

**アクションが並べば成功。** 何も起きない、または一部しか並ばない場合は、
「Robin リテラルのエスケープ」の節の切り分け手順を使う。要点は 2 つ。

- **4 ブロックに分けて貼る**（設定〜セッション開始／セットアップ／ループ／後片付け）と
  どこで弾かれているか特定できる
- **弾かれた行のアクション名が PAD のバージョンと違う可能性が高い。** PAD で同じアクションを
  1 つキャンバスに置いてコピー（Ctrl+C）してテキストに貼れば、その環境での正しい書式が分かる

`SET JsAct TO …` の継ぎ足しが通らなかった場合だけ、その行を削除して
「変数の設定」アクションを 1 つ置き、値の欄に共通 JavaScript の中身を直接貼る
（UI の入力欄なら長い文字列でも入る）。変数名は `JsAct`。中身はブラウザ版の
「共通 JavaScript をコピー」か、Python 版が出力する `pad_flow.jsact.js` から取る。

---

### 手順 ⑦：試走から本番へ

**⚠️いきなり全件流さない。** 生成時の既定は `MaxItems = 1` になっている。

| 回 | 設定 | 確認すること |
| --- | --- | --- |
| 1 回目 | `MaxItems = 1` | ブラウザが起動する／ログインできる／1 件が「成功」になる／エビデンスが開ける |
| 2 回目 | `MaxItems = 10` | 2 件目以降も通る／skip 行が飛ぶ／結果 CSV の列がずれない |
| 3 回目 | 失敗を仕込む | `fail__` の PNG が実体としてできる／次の件が復帰して成功する |

3 回目が**いちばん省略されやすく、いちばん重要**。成功経路だけ確認して配布すると、
最初の失敗が起きたときに証跡が無いことに気づく。やり方は「失敗経路の検証方法」の節に書いた。

### 手順 ⑧：出力を確認する

| 出力 | 内容 |
| --- | --- |
| `<ID>__<業務キー>__yyyyMMdd_HHmmss.png` | 成功時のエビデンス |
| `fail__<ID>__<業務キー>__yyyyMMdd_HHmmss.png` | 失敗時の画面 |
| `pad_result.csv` | ID・業務キー・結果・理由・エビデンス・実行日時 |
| `pad_progress.log` | 実行開始の区切り行、ドライバー確認の 1 行、1 件ごとの開始・成功・失敗、中止理由 |

`pad_result.csv` は**そのまま明細として読み直せる列構成**にしてある。失敗分と、件数上限で
打ち切った未実行分を流し直すには `RetryMode` を `True` にするだけ。

進捗ログは**中止したときも必ず 1 行以上残る**。実行開始のヘッダーはドライバーを触る前に
書いており、中止時は理由も書く。ログ書き込みをループの中だけに置くと、起点画面に着けずに
中止したとき「ログを確認してください」と案内しながらログが空、という状態になる。

> **⚠️ 登録系の再実行は二重登録に注意。** 再実行の前に `fail__` の画像で実際の画面を
> 確認すること。

### フローが増えたときの進め方

**2 本目以降はバッチ定義 JSON を差し替えるだけ。** 生成器・手順書・落とし穴の対処は
共通なので、1 本目で通った環境なら 2 本目は録画からフロー完成までが一気に進む。

ただし**フロー間で規約をそろえること。** 特に `--id-column` に何を指定するか、

② 人がログインする
③ [OK]を押す → 起点画面かどうかを確認してから明細の処理が始まる

### 見分けて除くのではなく、読まない

生成器は `setup` から **「ページを開く」と「ウィンドウサイズ」しか再生しない。**
入力（`change`）は読まないので、ログイン欄への入力が録画に残っていても

テストでも、録画に実際の値を入れて変換し、**生成物に一文字も現れないこと**を
毎回確かめている。

もう一度[OK]でやり直せる（何度でも試せる）。

## 手動ログイン

**ログインするのは人。起点画面まで進むのはフロー。**

```
① フローを実行 → ブラウザーが開く
② 人がログインする
③ [OK]を押す
④ フローが録画どおりにメニューを辿り、繰り返しの起点画面まで進む
⑤ 起点画面かどうかを確認してから、明細の処理が始まる
```

**④と⑤は繰り返す。** ログイン前に[OK]を押してしまっても、ログインしてから
もう一度[OK]を押せば、そこから起点まで進んで処理が始まる。

**録画はログイン直後から始める。** そうすれば録画にはメニュー移動だけが入り、
ID もパスワードも一度も現れない。

- PAD はパスワードを受け取らないので、変数ペインにも実行ログにも
  エラーメッセージにも残らない
- 生成物にも入らない。**録画に無いものは生成しようがない**
- ログインのしかたが変わっても（多要素認証が入る、など）フローは直さなくてよい

### 起点まではフローが進む

以前は起点画面まで人に進めてもらう方式だったが、**起点が分かりにくいサイトでは
説明が難しい。** 起点までのメニューは変わりにくいので、録画どおりに辿らせるほうが
確実で、利用者への案内も「ログインしたら[OK]」だけで済む。

移動が失敗しても止めない。**起点に着いたかどうかは次の確認で見る**ので、
そこで足りなければやり直せる（何度でも試せる）。

| `navigate`（ページを開く） | ○ |
| `setViewport`（ウィンドウサイズ） | ○ |
| `click`（メニューを辿る） | ○ |

## 📊 結果 CSV と再実行

列構成は、**その CSV をそのまま明細として読み直せる形**にする。

```
プロジェクト番号,発注番号,結果,理由,エビデンス,実行日時
```

ID だけでなく**業務キー（例では発注番号）も必ず含める**。これが無いと再実行時に対象を特定できない。

再実行はモードフラグ 1 つで実現できる。

```
SET RetryMode TO False
IF RetryMode THEN
    SET DetailsFile TO $'''%BaseDir%\\pad_result.csv'''
    SET ResultFile TO $'''%BaseDir%\\pad_result_retry.csv'''
END
```

ループ先頭で結果列を見て絞る。

```
IF RetryMode THEN
    SET DoRow TO False
    IF Row['結果'] = $'''失敗''' THEN
        SET DoRow TO True
    END
    IF Row['結果'] = $'''未実行''' THEN
        SET DoRow TO True
    END
    IF DoRow = False THEN
        NEXT LOOP
    END
END
```

**対象は「失敗」だけでなく「未実行」も含める。** `MaxItems` で打ち切った行は「未実行」で
記録されるため、失敗だけを拾う条件にすると、上限を小刻みにして回す運用で続きが流せない。
`AND` を使わず IF を並べているのは、複合条件の書式が実機で未検証のため。

**出力先は必ず別名にする。** 同じファイルを読みながら書くと壊れる。再実行 CSV には `skip` 列が
無いので、`skip` の判定は `IF RetryMode = False THEN` で囲む。

進捗ログには**失敗も書く**こと。失敗を結果 CSV にだけ書いていると、ログには「開始」だけが残り、
「成功が出ていない」ことから推測させる形になる。

> **⚠️ 登録系の再実行は二重登録に注意。**「実は登録は成功していたが確認段階で失敗扱いになった」
> ことがある。再実行の前に失敗時のエビデンスで実際の画面を確認すること。

## 🔗 登録した結果を次のバッチへ渡す

登録すると番号が発番され、**その番号を使ってあとから照会する**業務がある。
納入登録で要求 ID が出て、しばらく経ってから検収状況一覧を取りに行く、
というような形。

`capture` で画面の値を読み取ると、**結果 CSV の列として残る。**

```json
{"type": "capture", "selectors": [["#ShipDoneNo"]], "name": "要求ID"}
```

```
プロジェクト番号,発注番号,結果,理由,エビデンス,実行日時,要求ID
PM9000000001,900000000001,成功,,"C:\temp\…png",2026/08/24 10:00:00,9123456
```

**この結果 CSV を、そのまま次のバッチの明細として読める。** 列を足したり
並べ替えたりする必要はない。

```
① 納入登録バッチ    明細 → 登録 → 要求 ID を記録  → pad_result.csv
② 検収状況一覧バッチ pad_result.csv を明細として → {{要求ID}} で照会 → Excel を保存
```

読み取れなかったときは失敗として記録される。**空のまま先へ進むと、次のバッチが
「番号の無い行」を処理しようとして原因が分かりにくくなる**ため。

### ②の作り方

変換するとき、**「前のバッチの結果 CSV を明細にする」にチェック**を入れる
（Python 版は `--details-from-result`）。生成物はこうなる。

```
SET DetailsFile TO $'''%BaseDir%\\pad_result.csv'''      ← ①の結果を読む
SET ResultFile TO $'''%BaseDir%\\pad_result_2.csv'''     ← ②の結果はこちら
```

**出力先が別のファイルになる。** 同じファイルを読みながら書くと壊れるため。
①の結果は残るので、うまくいかなければ何度でもやり直せる。

> **チェックを入れ忘れると、元の明細 CSV を読んだまま動く。** 要求 ID の列が
> あれば処理は進んでしまい、**中身の合わないエビデンスが集まる**ので気づきにくい。
> ②を作るときは必ず確かめること。

> **実サイトでは発行から出力まで 1 分〜3 時間かかる。** ①と②を続けて流さず、
> 時間をおいて②を実行する。結果 CSV が残っているので、いつでも再開できる。

## 📥 エビデンスがファイルで届く場合

登録の結果が画面に出ず、**Excel や PDF をダウンロードして初めて内容が分かる**業務が
ある。スクリーンショットでは証跡にならないので、ファイルとして受け取って保存する。

バッチ定義では `download` を使う。**クリックと待機とリネームがこの 1 行に入っている。**

```json
{"type": "download",
 "selectors": [["#OutputIcon0"]],
 "name": "【検収状況一覧】{{プロジェクト番号}}_{{発注番号}}"}
```

生成されるフローは次のことをする。

1. 押す前のファイル数を数える
2. クリックする
3. `.crdownload` が消えて、かつ件数が増えるまで待つ（既定 60 秒）
4. 更新日時が一番新しいものを拾う
5. `name` の名前に付け替える

**拡張子はそのまま残る。** Excel でも PDF でも同じ 1 行で足りる。
落ちてこなかったときは失敗として記録され、次の明細へ進む。

### 受け取り先と確認ダイアログ

保存先は既定で `C:\temp\download`。変換器の**「ダウンロード保存先」**で変えられる
（Python 版は `--download-dir`）。フロー冒頭の `SET DlDir` と `SET DlDirJson` が
対になっているので、**貼り付けたあとに直すなら両方**を揃えること。

> **⚠️ ログや結果 CSV と同じフォルダにしないこと。** ダウンロードの判定は
> 「更新日時が一番新しいファイルを拾う」なので、待っている間に更新された
> `pad_progress.log` を拾って付け替えてしまう。

ブラウザーは素のプロファイルなので、指定しないと既定のダウンロードフォルダに
落ち、確認ダイアログも出る。生成器がセッション作成時に次の 4 つを渡している。

| 設定 | 効果 |
| --- | --- |
| `download.default_directory` | 保存先を固定する |
| `download.prompt_for_download` | 保存ダイアログを出さない |
| `plugins.always_open_pdf_externally` | **PDF をビューアで開かずファイルとして落とす** |
| `automatic_downloads: 1` | 「複数ファイルのダウンロードを許可しますか」を出さない |

**上の 2 つは別物。** `prompt_for_download` だけでは「ブロック / 許可」の確認が出て、
押すまでダウンロードが始まらない。

### 時間がかかる業務は実行を分ける

実 EDI では、発行してから出力できるようになるまで数時間かかることがある。
その場合は**登録とエビデンス取得を別々の実行に分ける。** 登録側の結果 CSV を
そのまま明細として読み直せるので、列を 1 つ足すだけで受け渡せる。

### 失敗経路の検証方法

成功経路が通っても、**失敗経路は一度も動いていない。** 本番で価値を持つのはむしろこちらなので、
配布前に一度は通しておく。

セレクタを壊すと全件が失敗して復帰の確認ができないため、**行によって結果が変わる仕掛け**を
一時的に入れる。挿入場所は**エビデンス保存の直前**（＝登録が完了し、起点ではない画面にいる状態）。

```
# ★テスト用（確認後に削除する）
IF Col2 = $'''<テスト用の業務キー>''' THEN
    SET RowError TO $'''テスト用の意図的な失敗（発行後）'''
    …既存の失敗ブロックと同じ処理…
    NEXT LOOP
END
```

明細は「失敗させる行 → 正常な行」の順に並べる。**2 行目が成功すれば復帰処理が効いている。**
これは「登録は成功したが確認段階で失敗と記録された」という、二重登録の危険が生まれる状況
そのものなので、一度実際に発生させておく意味がある。

## 🚚 練習できる業務フロー

練習サイト（`test_site/edi2/`）には 3 つの流れが入っている。バッチ定義は
`recordings/` にあり、そのまま変換して試せる。明細は `data/edi2_practice_batch.csv`。

| 流れ | バッチ定義 | 内容 |
| --- | --- | --- |
| 注文受諾 | `edi2_accept_batch.json` | 発注を受諾し、受理済になった発注情報をエビデンスにする |
| 納入登録 | `edi2_delivery_batch.json` | 発注番号で検索し、納入番号と納入日を入れて発行する |
| 検収状況一覧 | `edi2_report_batch.json` | 条件を入れて発行 → 要求IDが出る → Excel をダウンロードする |

### 3 つとも起点は「仕入先ホーム」

ログイン直後の画面から、3 つとも同じ道を通って起点に着く。

```
ナビゲータ → 「仕入先」→「取引情報入力・照会」→「ホームページ」→ 仕入先ホーム（起点）
```

この 3 クリックが `setup` に入っている。[OK]のあとフローが辿るので、
利用者は**ログインするだけ**でよい。

### 注文受諾

```
発注タブ → 発注 → 拡張検索 → 発注番号 → 進む → 検索結果の発注番号
→ 進む → 進む → 発行 → 受諾完了
→ 起点へ戻り、同じ発注番号を開き直してエビデンスを撮る
```

### 納入登録

```
納入タブ → 納入 → 納入登録 → 拡張検索 → 発注番号 → 進む
→ 検索結果を選択 → 納入に追加 → 納入ヘッダー
→ 納入番号（プロジェクト番号）と納入日を入力 → 発行確認 → 発行 → 完了
```

### 検収状況一覧（ファイルのダウンロード）

```
EBS ホーム → 帳票出力 → 検収状況一覧
→ ステータス・発注番号(From/To)・納入日(From/To) を入れて続行
→ 発行 → 要求ID がポップアップで出る → OK
→ 要求一覧で「出力」→ Excel がダウンロードされる
```

**実サイトでは、発行してから出力できるようになるまで 1 分〜3 時間かかる。** そのため
納入登録とエビデンス取得は別々の実行に分ける。練習サイトではすぐ取得できる。

# 第 5 部　困ったとき

---

## ❓ うまくいかないとき

- **社外サイトが真っ白になる** … WebDriver のブラウザーはシステムのプロキシを引き継がない。
  「社外サイトへ出る」の節を参照し、`UseProxy` を `True` にする。

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| ①で接続できない | ドライバーが起動していない / プロキシ | ポート 9515、プロキシ除外に `localhost` |
| `session not created` | Edge とドライバのバージョン不一致 / 古いドライバがポートを占有 | ドライバを入れ替える / 起動前にプロセス終了 |
| `invalid argument: missing command parameters` | 本文が URL エンコードされている | **`EncodeRequestBody: False`** |
| `無効な URI: URスキームが有効ではありません` | `Url:` に本文用の変数を渡している | URL 用の変数を渡す |
| `パラメーター 値:変数 X が存在しません` | 変数名の誤り、または未初期化 | 変数名を確認 |
| 貼り付けても何も起きない | 1 行が長すぎる / `'` が未エスケープ | 行を分割する / `\'` にする |
| 変数が展開されない | `\%` と書いている | `%` にする |
| ファイルパスが二重区切りになる | フォルダ変数の末尾に `\` | 末尾の `\` を外す |
| ④が `ok:false` | セレクタが古い | F12 で確認して候補を足す / 画面遷移直後なら待機を入れる |
| 検索 0 件なのに次へ進む | 隠れている要素をクリックしている | 可視判定を足す / `exists` で確認 |
| 画面遷移が間に合わない | 待機不足 | ④の前に 1〜2 秒待つか、`exists` で目的の文字が出るまで待つ |
| スクショが全画面 | PAD の標準アクションは全画面固定 | WebDriver の `/screenshot` を使う |
| PNG ができないのにエラーも出ない | `IfExists.DoNothing` で静かに通過 | 実体を目で確認する |
| 1 件失敗したら以降も全部失敗 | 失敗した画面のまま次の件を始めている | 復帰処理を入れる |
| 全件が「ステップ 1 で失敗」 | セットアップ（ログイン）が失敗している | セットアップ失敗の検知を入れる |
| ファイル名の月が変な数字 | `yyyymmdd` と書いた（`mm` は分） | `yyyyMMdd` |
| 実行後もブラウザが残る | 後片付けを通っていない | ⑥の DELETE と `System.TerminateProcess` を最後に必ず通す |

# 第 6 部　上級者向け

---

## 🧑‍💻 上級者向け

Python が使える環境向けの機能です。**使わなくても、ブラウザー版だけで
すべてのことができます。**

#### 上級者向け: Python版の変換器 `pad_webdriver_ref.py`
```
# Python版の変換器を使う場合は Python必要。（ブラウザ、WebDriver は不要）
python pad_webdriver_ref.py --batch recordings/edi2_practice_batch.json `
    --details "C:\temp\edi2_batch.csv" --id-column "プロジェクト番号" `
    --robin output/pad_flow.robin.txt `
    --driver-exe "C:\temp\msedgedriver.exe" --pad-out-dir "C:\temp"
```

**引数のパスは 2 種類あるので混ぜないこと。**

| 引数 | どのマシンのパスか |
| --- | --- |
| `--batch` / `--robin` | **変換環境**（Python が使える PC）のパス。リポジトリ相対でよい |
| `--details` / `--driver-exe` / `--pad-out-dir` | **実行環境**（PAD を動かす PC）のパス。生成された Robin に文字列として埋め込まれる |

| 引数 | 役割 |
| --- | --- |
| `--batch` | バッチ定義 JSON（③で作ったもの） |
| `--details` | 明細 CSV のパス。`SET DetailsFile` になる |
| `--id-column` | ID 列の名前。この列が `Col1` になり、進捗・結果・再実行のキーになる |
| `--robin` | 出力先。同名で `.jsact.js` も一緒に出る（ブラウザ版はコピーのみ） |
| `--driver-exe` | `msedgedriver.exe` のパス。`SET DriverExe` になる |
| `--pad-out-dir` | 出力フォルダ。`SET BaseDir` になる |

`--details` と `--driver-exe` が `--pad-out-dir` の配下にある場合、生成される Robin は
それらを `%BaseDir%` 相対で出力する。上の例なら次のようになり、**配布時に直すのは
`BaseDir` の 1 行だけ**で済む。

```
SET BaseDir TO $'''C:\\temp'''
SET DriverExe TO $'''%BaseDir%\\msedgedriver.exe'''
SET DetailsFile TO $'''%BaseDir%\\edi2_batch.csv'''
SET ResultFile TO $'''%BaseDir%\\pad_result.csv'''
SET LogFile TO $'''%BaseDir%\\pad_progress.log'''
SET ShotDir TO $'''%BaseDir%'''
```

配下でないパスを渡した場合は絶対パスのまま出力されるので、環境ごとに 3 行を直すことになる。

### （任意）手順書だけを出す　　　※ Python版のみ

`--robin` の代わりに `--trace` を使うと、**PAD が送るのと同じ HTTP 呼び出しを同じ順序で
実際に送りながら**、その呼び出し列を Markdown の表として書き出せる。フローを人に説明する
資料や、生成物が期待どおりか確かめる用途に使う。

```
# 別ターミナルでWebドライバーを実行しておく: msedgedriver.exe --port=9515
# 手順書生成
python pad_webdriver_ref.py --batch recordings/edi2_practice_batch.json `
    --details data/edi2_practice_batch.csv --trace output/pad_trace.md
```

「何番目に・どのメソッドで・どの URL へ・どんな本文を送るか」が全件出力される
（セッション ID は `{session}` に伏せ、秘密情報は `[SECRET:名前]` の表記で残らない）。
